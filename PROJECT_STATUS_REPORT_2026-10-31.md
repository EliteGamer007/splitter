**Splitter project status report — 31 October 2026**

Splitter remains a substantial college project with a Go/Echo backend, PostgreSQL persistence, a Next.js interface, and considerable social-network and federation functionality. Both parts build, and the current public frontend at https://splitter-social.vercel.app works with both APIs through CORS. The earlier conclusion that the public demo was broken was incorrect: the initial audit checked the obsolete URL in the README and did not discover the replacement. Several advertised capabilities were intentionally disabled in current main in May, and the source contains authentication and privacy defects that should be addressed before accepting real users or demonstrating private-data features.

This corrected report combines live public HTTP checks, public GitHub metadata, inspection of both repositories, fresh local builds/tests, dependency scans, and browser checks of both the live and locally built frontend. The user supplied the current frontend URL after the initial audit; it was verified on 31 October 2026 at approximately 21:36 IST. Deployed frontend/backend commit IDs remain unverified, so source findings must not be treated as remotely reproduced flaws in those exact deployed binaries.

**The most urgent source defects concern authentication and private data.** Severity below reflects the consequence of the implementation if exposed. These were established through source tracing; no production account takeover, private-post retrieval, federation forgery or credential guessing was attempted.

1. **Critical — DID login does not verify a signature.** The public challenge endpoint supplies a nonce. `VerifyChallenge` checks the nonce and expiry, looks up the user and issues their JWT, without verifying `req.Signature` against the user's public key. It also omits the suspension check used in password login. Knowledge of an existing DID is sufficient to reach token issuance through this code path. This includes administrator identities. Add actual signature verification and negative handler-level tests before restoring this flow. [auth_handler.go:319](https://github.com/EliteGamer007/splitter/blob/25bd3a944bac2220007d9e4d2cf203254961563e/internal/handlers/auth_handler.go#L319), [public routes:155](https://github.com/EliteGamer007/splitter/blob/25bd3a944bac2220007d9e4d2cf203254961563e/internal/server/router.go#L155)

2. **Critical — startup resets an administrator to a hardcoded password.** `ensureAdminUser` runs on every startup. It restores the existing domain-specific admin's password and admin role, or creates the administrator, and logs the default password on creation. Changing the database password alone is undone by the next restart. Replace this with explicit, controlled bootstrap/provisioning and rotate deployed credentials after removing the reset behavior. [main.go:66](https://github.com/EliteGamer007/splitter/blob/25bd3a944bac2220007d9e4d2cf203254961563e/cmd/server/main.go#L66), [password/reset:135](https://github.com/EliteGamer007/splitter/blob/25bd3a944bac2220007d9e4d2cf203254961563e/cmd/server/main.go#L135)

3. **High — private post visibility is bypassed by public reads.** `GetPost` returns a record without checking the viewer or visibility. `GetUserPosts` queries all undeleted, unexpired posts by author, with no followers/circle authorization. Filtering the main feed does not protect these other endpoints. Enforce visibility centrally across post, profile, thread, reply and media reads. [post_handler.go:174](https://github.com/EliteGamer007/splitter/blob/25bd3a944bac2220007d9e4d2cf203254961563e/internal/handlers/post_handler.go#L174), [user posts:344](https://github.com/EliteGamer007/splitter/blob/25bd3a944bac2220007d9e4d2cf203254961563e/internal/handlers/post_handler.go#L344), [post_repo.go:286](https://github.com/EliteGamer007/splitter/blob/25bd3a944bac2220007d9e4d2cf203254961563e/internal/repository/post_repo.go#L286)

4. **High — denied moderators can continue into administrator operations.** `requireAdmin` returns the result of writing a JSON 403 response, which normally returns `nil`. Its callers interpret `nil` as permission to continue. Outer middleware admits moderators, so an administrator-only mutation can execute after the denial response. Separate permission checks from response writing and test that rejected calls make no database changes. JWT roles also remain trusted for a seven-day token lifetime after a role change. [admin_handler.go:55](https://github.com/EliteGamer007/splitter/blob/25bd3a944bac2220007d9e4d2cf203254961563e/internal/handlers/admin_handler.go#L55), [role mutation:180](https://github.com/EliteGamer007/splitter/blob/25bd3a944bac2220007d9e4d2cf203254961563e/internal/handlers/admin_handler.go#L180), [token.go:27](https://github.com/EliteGamer007/splitter/blob/25bd3a944bac2220007d9e4d2cf203254961563e/internal/auth/token.go#L27)

5. **High — editing an encrypted DM sends and stores plaintext.** The frontend encrypts the edit but passes both `editMessage` and ciphertext to the API. The backend stores both `content` and `ciphertext`. This directly contradicts the claim that the server never sees message plaintext. New sends can also fall back to plaintext when encryption is loading or has errored. Encrypted conversations should fail closed and send no plaintext content field. [DMPage.jsx:377](https://github.com/Jaswita/Splitter-frontend/blob/03e0a1be05b58cc9604f80f76e0ea38e479c7cd9/components/pages/DMPage.jsx#L377), [api.ts:687](https://github.com/Jaswita/Splitter-frontend/blob/03e0a1be05b58cc9604f80f76e0ea38e479c7cd9/lib/api.ts#L687), [message_repo.go:485](https://github.com/EliteGamer007/splitter/blob/25bd3a944bac2220007d9e4d2cf203254961563e/internal/repository/message_repo.go#L485), [send fallback:478](https://github.com/Jaswita/Splitter-frontend/blob/03e0a1be05b58cc9604f80f76e0ea38e479c7cd9/components/pages/DMPage.jsx#L478)

6. **High — encryption key lifecycle can lose access to old messages or reuse keys across accounts.** ECDH keys use browser-global storage names. Logout leaves them behind. Login and DM initialization upload that browser's public key unconditionally, so another account can reuse the key and a new browser can silently replace an existing account key. Account/device-scoped keys, authenticated key changes, history preservation and a genuine recovery mechanism are needed. [crypto.ts:494](https://github.com/Jaswita/Splitter-frontend/blob/03e0a1be05b58cc9604f80f76e0ea38e479c7cd9/lib/crypto.ts#L494), [LoginPage.jsx:84](https://github.com/Jaswita/Splitter-frontend/blob/03e0a1be05b58cc9604f80f76e0ea38e479c7cd9/components/pages/LoginPage.jsx#L84), [logout:182](https://github.com/Jaswita/Splitter-frontend/blob/03e0a1be05b58cc9604f80f76e0ea38e479c7cd9/app/page.tsx#L182)

7. **High — cached private timeline content survives logout.** Timeline storage keys use only the active tab, without account/instance identity; logout does not clear them. Another account on the same browser can receive the previous user's cached home/circle content while offline. Thread caches have similar scoping problems. [HomePage.jsx:483](https://github.com/Jaswita/Splitter-frontend/blob/03e0a1be05b58cc9604f80f76e0ea38e479c7cd9/components/pages/HomePage.jsx#L483), [cache writes:608](https://github.com/Jaswita/Splitter-frontend/blob/03e0a1be05b58cc9604f80f76e0ea38e479c7cd9/components/pages/HomePage.jsx#L608), [ThreadPage.jsx:198](https://github.com/Jaswita/Splitter-frontend/blob/03e0a1be05b58cc9604f80f76e0ea38e479c7cd9/components/pages/ThreadPage.jsx#L198)

8. **High — inbound federation authenticity is incomplete.** The inbox may replace an actor's key with a separately resolved `Signature.keyId` key without binding signer to actor. HTTP signature verification does not check the actual body against `Digest`, enforce required signed headers or check Date freshness. Delete activities are not checked against object ownership. Inbound routes remain registered even though outbound federation is disabled. Do not equate the federation-off setting with protection of these inboxes. [inbox_handler.go:89](https://github.com/EliteGamer007/splitter/blob/25bd3a944bac2220007d9e4d2cf203254961563e/internal/handlers/inbox_handler.go#L89), [http_signatures.go:84](https://github.com/EliteGamer007/splitter/blob/25bd3a944bac2220007d9e4d2cf203254961563e/internal/federation/http_signatures.go#L84), [delete handling:628](https://github.com/EliteGamer007/splitter/blob/25bd3a944bac2220007d9e4d2cf203254961563e/internal/handlers/inbox_handler.go#L628)

9. **High — restoring outbound federation could publish private posts.** The post-creation hook does not branch on visibility before federation, and the activity builder addresses the public collection. Repair visibility semantics before enabling delivery. [post_handler.go:132](https://github.com/EliteGamer007/splitter/blob/25bd3a944bac2220007d9e4d2cf203254961563e/internal/handlers/post_handler.go#L132), [delivery.go:311](https://github.com/EliteGamer007/splitter/blob/25bd3a944bac2220007d9e4d2cf203254961563e/internal/federation/delivery.go#L311)

10. **High — public profile responses include email addresses.** The repository populates the complete User model and public profile handlers serialize it, including email. Use separate public/private response types. [user_handler.go:37](https://github.com/EliteGamer007/splitter/blob/25bd3a944bac2220007d9e4d2cf203254961563e/internal/handlers/user_handler.go#L37), [user_repo.go:77](https://github.com/EliteGamer007/splitter/blob/25bd3a944bac2220007d9e4d2cf203254961563e/internal/repository/user_repo.go#L77), [user.go:13](https://github.com/EliteGamer007/splitter/blob/25bd3a944bac2220007d9e4d2cf203254961563e/internal/models/user.go#L13)
